System design

More than a chatbot.

Red Queen is built as a local agent system with explicit separation between conversation, memory, model inference and tool authority. The LLM does not receive unrestricted control of the computer.

User→Red Queen→Letta→Qwen / Ollama→Tool Controller→Approved tools

Letta handles conversational memory; Obsidian provides structured long-term knowledge. Protected actions remain controller-owned and approval-gated.

Local inferenceQwen through Ollama with no cloud AI runtime dependency.
Persistent memoryConversational memory plus structured Obsidian knowledge.
Desktop toolsFiles, applications, documents, browser actions and coding workflows.
Voice & visionLocal voice workflow and request-only screen vision under explicit controls.
3D Control CenterA state-aware interface that exposes agent activity rather than hiding it.
Bounded automationTask execution designed around permissions, approvals and observable state.
Security by design

The controller is the final authority.

The security model is intentionally conservative: protected operations require scoped approval, generic shell/admin access is not exposed, and screen vision is isolated from direct action execution.
